# ERROR RECORD — Nosok v09

## 1) تضارب مسار الإدارة السابق
- السبب: بعض الدفعات السابقة استخدمت `/admin/nosok` بينما العقد الحاكم يميل إلى system namespace.
- الأثر: احتمال تعارض/تشتت داخل لوحة إدارة المنصة.
- الحل في v09: اعتماد `/admin/systems/nosok` كمسار حاكم، وإبقاء `/admin/nosok` redirects فقط.
- آخر baseline مستقر: v09.

## 2) خطر تكرار المستخدمين داخل النظام
- السبب: طلب صفحات المستخدمين والأدوار والصلاحيات قد يفسر خطأ كإنشاء RBAC مستقل داخل نسك.
- الأثر: source-of-truth drift مع منصة PalWakf.
- الحل في v09: صفحة المستخدمين والأدوار تعرض قوالب RBAC فقط، ولا تنشئ مستخدمين داخل `nosok`.
- آخر baseline مستقر: v09.

## 3) صفحات الوحدات قد تتحول إلى source-of-truth بديل
- السبب: إضافة unit pages قد تغري بتكرار core.org_units.
- الأثر: تضارب ملكية بين core وnosok.
- الحل في v09: إنشاء `nosok.unit_service_scopes` كإعداد سطح خدمة فقط، مع توثيق أن `core.org_units` هو المرجع.
- آخر baseline مستقر: v09.

## 4) visibility بدون route guard
- السبب: وجود sidebar داخلي قد يخفي/يظهر عناصر دون حماية فعلية.
- الأثر: فجوة أمنية أو UX مضلل.
- الحل في v09: توثيق أن السايدبار ليس صلاحية، وإضافة صفحة RBAC/Role templates وUAT مطلوب للـ route guards.
- آخر baseline مستقر: v09.
